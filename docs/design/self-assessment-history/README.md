# Self-assessment history mockups

Both alternatives show the empty history, fictional example entries, and the saved Audit Structure picker used to start a self-assessment. They were made with the built-in ImageGen tool using the supplied Kafaa screenshot.

- [Option 1 · Cards and a full-screen form](01-cards-and-full-screen.png) uses separate draft and submitted cards with the Start action anchored at the bottom.
- [Option 2 · Timeline and a bottom sheet](02-timeline-and-bottom-sheet.png) uses chronological rows and keeps history visible behind the form.

## Generation prompts

### Option 1

```text
Use case: ui-mockup. Deliver ONE landscape PNG design board (~3:2) for Kafaa's mobile self-assessment history and creation flow. Image 1 is a reference for actual screen and branding. Take the centre name verbatim from the reference: "Bousher Renal Dialysis Centre". Design three equal flat mobile screen columns side by side, with a subtle edge around each screen, no device bezels. Mobile proportions around 390×800 logical px, legible app-scale text and even gutters. Use Kafaa's white and very light blue-gray surfaces, deep navy typography, existing medium blue for primary actions, restrained pale blue/teal status fills and cool gray borders. Practical Material-style Flutter UI with natural whitespace and strong contrast. No visual noise, graphics beyond simple line icons, fake branding, charts, phone hardware, operating system toolbar or watermark. At the top of the board, three small aligned external captions only: "Empty history", "Example history", and "Start a self-assessment". All history examples are fictional. Use identical samples across concepts: "Audit Structure v 1.00" with status "Draft", "Revision 1", date "14 Nov 2026"; another "Audit Structure v 1.00" with status "Submitted", "Revision 1", date "6 Nov 2026". Only the draft has a "Continue draft" action. Submitted rows open read-only and say "View assessment" or use a chevron. No duplicate history navigation link. Visible history screen app bar has a back arrow and "Self-audit history" followed by the actual centre name. The start flow picks a saved Audit Structure only, no name/date/notes/period/scheduling fields. Its visible picker label is "Saved Audit Structure"; selected value "Audit Structure v 1.00"; caption "79 items · 237 maximum points"; main confirmation "Start with v 1.00". Selecting a version is visually separate from starting. Keep text verbatim, no duplicate data, all controls fully visible, nothing clipped.
Concept 1: a history page with roomy cards and a dedicated full-screen start screen. In the left empty-history panel, below centre name, use a white bordered empty card: simple clipboard outline, heading "No self-assessments yet", helper "Start with a saved Audit Structure." The main blue button "+ Start self-assessment" is full-width and fixed in the bottom action area used consistently in both history panels. Use only one start button per screen. The middle example-history panel has two generous stacked cards and exactly the same bottom start button. The draft card puts the structure title and a pale amber "Draft" chip high on the card, followed by "Revision 1 · 14 Nov 2026" and an outlined "Continue draft" button. The submitted card uses a muted teal "Submitted" chip, "Revision 1 · 6 Nov 2026", and a plain "View assessment" action with a chevron. The right panel is a separate full-screen page with a back arrow and title "Start self-assessment", centre name underneath, one white form card containing the saved structure dropdown and its metrics line, and the blue bottom button "Start with v 1.00". The new screen has no visible overlay and no history cards. Visually prioritize readable type and show the difference between the two history states.
```
